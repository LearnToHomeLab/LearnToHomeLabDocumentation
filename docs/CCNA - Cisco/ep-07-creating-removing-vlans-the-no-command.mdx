### Create and Name Custom Department VLANs
> The `vlan <id>` global configuration command creates a broadcast domain; `name <string>` assigns an organizational label.

Segment departments (Engineering, Finance, Guests) to restrict Layer 2 broadcasts.

<InfoBox emoji="📌" title="Key Exam Concept">
  Review protocol interactions, default timers, and packet/frame header fields before deploying this feature in production.
</InfoBox>

### Confirm VLAN Creation in the Active Database
> Verify that new VLANs appear in `show vlan brief` with active status after exiting `config-vlan` mode.

Validates that VLAN definitions are committed to `vlan.dat` in Flash memory.

```cisco
Switch# configure terminal
Switch(config)# vlan 10
Switch(config-vlan)# name Engineering
Switch(config-vlan)# vlan 20
Switch(config-vlan)# name Sales
Switch(config-vlan)# exit
Switch(config)# no vlan 20
Switch(config)# end
```

| Verification Command | Purpose & Key Output Fields to Inspect |
| :--- | :--- |
| `show vlan brief` | Verify operational status, administrative flags, and active state |

```cisco
Device# show vlan brief
! Confirm operational readiness and healthy state
```

### Decommission Broadcast Domains using `no vlan <id>`
> Removing a VLAN deletes it from `vlan.dat` stored in Flash memory.

Applied when repurposing campus switch networks or cleaning legacy configurations.

### Analyze Orphaned Access Ports on Deleted VLANs
> Access ports assigned to a deleted VLAN become orphaned and cease forwarding traffic until reassigned to an active VLAN.

Key troubleshooting check when endpoints suddenly lose network connectivity.

<WarningBox>
  Always verify that configuration changes are committed to NVRAM using 'copy running-config startup-config'. Mismatched parameters, unassigned VLANs, or missing 'no shutdown' commands will disrupt link forwarding.
</WarningBox>
