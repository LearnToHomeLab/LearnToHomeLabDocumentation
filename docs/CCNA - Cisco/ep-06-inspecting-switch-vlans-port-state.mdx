## Inspecting Switch VLANs & Port State
In this episode, we focus on **Inspecting Switch VLANs & Port State**. We examine the core networking principles, Cisco IOS CLI syntax, verification show commands, and common troubleshooting traps according to the official CCNA 200-301 certification blueprint.

<InfoBox emoji="ℹ️" title="Throughout this course">

## Learning Objectives
1. Analyze Normal-Range VLAN Assignments in the Factory Default State
2. Inspect Reserved Legacy VLANs (1002 - 1005)
3. Differentiate Access Ports from Trunk Links in VLAN Output

### Analyze Normal-Range VLAN Assignments in the Factory Default State
> By default, all switchports belong to VLAN 1 (the default data and management VLAN).

Used to determine broadcast domain boundaries and identify unassigned ports.

<InfoBox emoji="📌" title="Key Exam Concept">
  Review protocol interactions, default timers, and packet/frame header fields before deploying this feature in production.
</InfoBox>

### Inspect Reserved Legacy VLANs (1002 - 1005)
> VLANs 1002-1005 are reserved for legacy FDDI and Token Ring protocols and cannot be deleted.

Critical for understanding reserved identifiers in normal-range switching.

```cisco
Switch# show vlan brief
Switch# show interfaces status
Switch# show vlan id 1
```

| Verification Command | Purpose & Key Output Fields to Inspect |
| :--- | :--- |
| `show vlan brief` | Verify operational status, administrative flags, and active state |

```cisco
Device# show vlan brief
! Confirm operational readiness and healthy state
```

### Differentiate Access Ports from Trunk Links in VLAN Output
> Access ports show up explicitly in `show vlan brief`; trunk ports do not because they carry all VLANs.

Essential audit step to prevent traffic leakage across isolated broadcast domains.

<WarningBox>
  Always verify that configuration changes are committed to NVRAM using 'copy running-config startup-config'. Mismatched parameters, unassigned VLANs, or missing 'no shutdown' commands will disrupt link forwarding.
</WarningBox>
